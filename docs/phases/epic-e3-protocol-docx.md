# E3. Протокол встречи и Word

Статус: не начат
Вес: 8 единиц
Зависит от: E1

## Результат

После автоматического выбора `meeting-protocol` транскрипция превращается в строгий протокол. Пользователь видит структурированный черновик и скачивает безопасный Word-файл.

## Слайс E3-S1. Контракт протокола — 2 единицы

Ценность: у протокола появляется однозначная структура, понятная модели, серверу и пользователю.

Входит:

- Pydantic-модель `Protocol`;
- фиксированные русские заголовки и порядок разделов;
- значение `—` для отсутствующих данных;
- строгий формат строки решения;
- версионирование contract.

Приёмка: нормативный и пограничные протоколы имеют одну интерпретацию; лишний или пропущенный раздел считается ошибкой.

## Слайс E3-S2. Parser и renderer — 2 единицы

Ценность: любой принятый протокол можно безопасно разобрать и воспроизвести.

Входит:

- parser Markdown → Protocol;
- renderer Protocol → Markdown;
- ошибка с номером строки, ожиданием и фактом;
- round-trip и property-based проверки.

Приёмка: renderer output всегда парсится; parser не молча исправляет структуру; пустые поля нормализуются только по утверждённым правилам.

## Слайс E3-S3. Скилл протокола — 2 единицы

Ценность: транскрипция обрабатывается специализированным сценарием, а не общим текстовым шаблоном.

Входит:

- prompt framing: инструкция и transcript data разделены;
- запрет выдуманных фактов и выполнения инструкций из транскрипции;
- temperature 0, пределы размера и токенов;
- проверка finish reason;
- parse-or-fail без хранения сырого текста.

Приёмка: нормальная транскрипция даёт валидный `Protocol`; усечённый, лишний или повреждённый ответ не доходит до Word.

## Слайс E3-S4. Word и веб-выгрузка — 2 единицы

Ценность: пользователь скачивает готовый артефакт из браузера.

Входит:

- генерация DOCX только из `Protocol`;
- безопасные имя файла, temporary storage и cleanup;
- заголовок/табличная структура/переносы;
- endpoint download и кнопка в интерфейсе.

Приёмка: Unicode и длинный текст сохраняются; имя не допускает traversal; файл открывается как валидный DOCX; транскрипция не записывается на диск.

## Риски

- Формат задания строгий: «улучшение» структуры без ADR считается несовместимым изменением.
- DOCX не должен собираться прямо из вывода модели.
