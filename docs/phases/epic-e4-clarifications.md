# E4. Уточнения и качество протокола

Статус: принят. As-built: `build_clarifications` / `apply_answers` / `verify` / `finalize`; HTTP `POST /protocol/clarifications`, `/answer`, `/finalize`; таблица уточнений на `GET /protocol`.
Вес: 8 единиц
Зависит от: E3

## Результат

Недостающие важные данные превращаются в конечный список вопросов. Пользователь отвечает, пропускает или отменяет решение для каждой строки, после чего сервер детерминированно формирует и проверяет финальный протокол.

## Слайс E4-S1. Детерминированные уточнения — 2 единицы

Ценность: пользователь видит только вопросы, на которые реально можно ответить.

Входит:

- вопросы выводятся из полей `Protocol`, а не свободным вторым вызовом модели;
- причина, подсказка и целевое поле;
- стабильный identifier и статус `pending`;
- максимальное число и приоритет вопросов.

Приёмка: одинаковый Protocol даёт одинаковый список; вопрос имеет одно целевое поле; необязательная косметика не блокирует финализацию.

## Слайс E4-S2. Таблица решений — 2 единицы

Ценность: каждая проблема закрывается понятным действием.

Входит:

- колонки «Проблема / Ответ / Действия / Статус»;
- stakeholder placeholder;
- `Отправить`, `Пропустить`, `Отменить выбор`;
- серверная и клиентская валидация;
- блокировка строки после решения.

Приёмка: пустой ответ не принимается; skip не требует текста; cancel возвращает pending; браузерная блокировка не заменяет серверную проверку.

## Слайс E4-S3. Финализация — 2 единицы

Ценность: пользователь получает итог только после явного решения по всем вопросам.

Входит:

- «Сформировать итоговый протокол»;
- сервер отклоняет pending rows;
- ответы применяются к разрешённым полям;
- skipped сохраняет `—`;
- повторный renderer/parser;
- модель повторно не вызывается.

Приёмка: незакрытая строка даёт конфликт и не меняет черновик; финализация идемпотентна; чужой identifier и лишнее поле отклоняются.

## Слайс E4-S4. Grounding и сложные транскрипции — 2 единицы

Ценность: протокол устойчивее к шуму и не повышает статус обсуждения без основания.

Входит:

- verifier для решений, задач, сроков и ответственных;
- правило «обсуждали ≠ решили»;
- сценарии speaker labels, без speaker labels, шум, противоречия, большие входы;
- тесты атакующих фрагментов внутри транскрипции.

Приёмка: неподтверждённое решение не принимается как факт; конфликт попадает в `unconfirmed`, итоговый `Protocol` при этом собирается; большие входы завершаются предсказуемой ошибкой.

## Риски

- Уточнения не являются отдельным скиллом: это состояние workflow `meeting-protocol`.
- Ответ пользователя доверен только после валидации целевого поля и длины.
