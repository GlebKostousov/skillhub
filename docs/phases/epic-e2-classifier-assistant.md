# E2. Автовыбор режима и обычные ответы

Статус: принято
Вес: 8 единиц
Зависит от: E1

## Результат

Пользователь формулирует задачу и добавляет материал. Классификатор выбирает один из пяти скиллов или `none`. Четыре простых режима возвращают реальный текстовый ответ, выбранный режим виден в интерфейсе.

## Слайс E2-S1. Изолированный шлюз модели — построено

Ценность: приложение безопасно обращается к DeepSeek через одну типизированную границу.

Сделано:

- ключ только из `DEEPSEEK_API_KEY`, без префикса `SKILLHUB_` и без файла окружения;
- адаптер `httpx` с фиксированным URL, timeout и пределом выходных токенов;
- типизированные request/result/usage;
- `FakeLlmGateway` как публичный тестовый шов, production его сам не выбирает.

Приёмка: успешный и каждый ошибочный ответ поставщика становится стабильным результатом или ошибкой; ключ и content не попадают в логи. Старт без ключа даёт `generation_unavailable`.

## Слайс E2-S2. Классификатор — построено

Ценность: режим выбирается автоматически, а нерелевантная задача честно отклоняется.

Сделано:

- в модель уходят только `intent` и `description[:250]`;
- маленький структурированный ответ `{"skill": "<имя>"}` или `null`;
- allowlist из снимка метаданных;
- fail-closed для unknown/invalid/none.

Приёмка: материал не попадает в classifier prompt; неизвестное имя не запускает обработчик.

## Слайс E2-S3. Общий обработчик простых режимов — построено

Ценность: перевод, резюме, задачи встречи и деловое сообщение реально работают.

Сделано:

- `PromptSkillHandler` и `SkillHandlerRegistry` для четырёх простых имён;
- тело выбранного `SKILL.md` как доверенная инструкция;
- material как отдельные недоверенные данные;
- `meeting-protocol` может быть выбран, но даёт `handler_unavailable` без вызова generate.

Приёмка: каждый из четырёх режимов получает собственную инструкцию; HTML остаётся текстом; body одного скилла не используется другим.

## Слайс E2-S4. Окно ассистента и classifier matrix — построено

Ценность: пользователь видит понятный основной сценарий и факт автоматического выбора.

Сделано:

- поля «Что нужно сделать» и «Материал для обработки» на `GET /`;
- состояния loading/error/success/none и остальные исходы;
- badge выбранного режима и список пяти режимов только для чтения без ручного выбора;
- `POST /api/assistant` с CSRF, same-origin, UTF-8 и лимитом 1 МБ;
- снимок скиллов только из `SkillRegistry.capture()` / `snapshot`;
- `eval/classifier_matrix.md`: не меньше 30 размеченных intent, все пять классов и `none`, без unknown.

Приёмка: четыре простых режима и `none` демонстрируются через `FakeLlmGateway`; выбор `meeting-protocol` показывает бейдж и `handler_unavailable`. Живой порог 95% без ключа не является красным gate; runner и схема матрицы готовы.

## Риски

- Визуальный список не должен превращаться в ручной выбор и маскировать ошибки классификатора.
- Generic handler не означает generic permissions: у модели по-прежнему нет инструментов.
- `outcome.text` и любые недоверенные строки показываются через Jinja autoescape и JS `textContent`, не через `innerHTML`.
