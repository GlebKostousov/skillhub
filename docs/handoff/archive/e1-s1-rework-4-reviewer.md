## B. System design

- Place: `core/_redaction.py` отвечает только за границу безопасного машинного лога: отбор текущих диагностических полей, безопасное представление значений и итоговый byte cap. Прикладных контрактов следующих слайсов модуль больше не моделирует.
- Contracts/errors: разрешены только текущие `event`, `error_code`, `status_code`, `error_type`, `request_id`, `level`, `timestamp` и только как ограниченные `str`, `None`, `bool`, 64-bit `int` либо конечный `float`. Неподдерживаемое значение известного диагностического поля явно становится `[UNSUPPORTED]`; значение неизвестного поля — `[REDACTED]`; нестроковый ключ — `[UNSUPPORTED]`; превышение числа полей — `[TRUNCATED]`; превышение итогового размера даёт фиксированный `log.truncated`.
- SoT/idempotency: список текущих диагностических полей и правила скаляров сосредоточены в одном приватном модуле. Обработка не создаёт состояния между событиями и не зависит от identity объектов.
- Scale/observability: вложенные контейнеры не обходятся и не интерпретируются. Диагностические коды и корреляционный `request_id` остаются разрешёнными текущими скалярами, а неизвестные данные не становятся новым языком payload.

## C. Архитектура vs canon

Изменение соответствует минимальному `core` и принципу «WMS-дисциплина без масштаба WMS». Прежний универсальный redaction mini-framework удалён: нет рекурсии по `dict/list/tuple`, множества identity, маркера `[REFERENCE]`, depth/node/text budgets и будущих прикладных полей. Оставшийся bounded JSON renderer реализует единственный требуемый предел сериализованного события, а не отдельную модель object graph.

## D. Читаемость / понятность

Модуль сократился до линейной цепочки из четырёх небольших операций: ограничить строку, распознать текущее диагностическое имя, проверить скаляр и сериализовать результат. Названия констант и ветви для неизвестных и неподдерживаемых значений однозначны; скрытого рекурсивного поведения нет.

Просто: лог пропускает значения только семи технических полей. Всё неизвестное скрывается, неподдерживаемый технический тип помечается, слишком большое событие заменяется фиксированным сообщением. Вложенные объекты не исследуются, поэтому модуль больше не рассуждает о ссылках, циклах или глубине.
