  [`src/skillhub/registry/_windows_reparse.py:36-65,156-214`] принимает

## B. System design

- Parent semantics сохранена: обычный потомок открывается через
  `NtCreateFile` относительно переданного родительского дескриптора. После
  ссылки безопасная цель раскладывается на компоненты от удерживаемого root,
  поэтому абсолютная строка UNC не используется для открытия содержимого.
- Resolver остаётся итеративным. Одна очередь и один общий бюджет учитывают
  компоненты и переходы по ссылкам; второй путь инициализации state machine
  удалён.
- Владение ресурсами однозначно: probe-токен закрывается в `finally`,
  обнаруженный после открытия raced reparse token закрывается до нового
  обхода, ошибочный metadata-path закрывает свой token, а замена или выход
  закрывает единственный owned intermediate parent. Заимствованные root и
  initial parent resolver не закрывает; возвращаемый handle остаётся у
  вызывающего кода.
- Граница модулей не размыта: ABI остаётся в `_windows_abi`, операции с
  дескрипторами — в `_windows_handles`, перечисление — в
  `_windows_directory`, чистый parser/normalizer — в `_windows_reparse`,
  алгоритм обхода — в `_windows_resolver`, сборка адаптера — в
  `_windows_io`.
- Публичный контракт `skillhub.registry` не менялся:
  `SkillRegistry`, модели и `MAX_SKILL_FILE_BYTES` экспортируются как прежде.
  `_windows_io.__all__` также сохранил прежние пять операций адаптера.
- Проверенные крайние случаи fail-closed: UNC другого share, UNC при локальном
  root, неполный UNC, device namespace, внешний путь, переполнение общего
  бюджета, ссылка на недиректорию в середине пути и ошибки чтения metadata.

## C. Архитектура относительно канона

Направление `core ← registry ← web` сохранено. Дельта находится внутри
приватного platform adapter реестра; `_registry.py` и семантическая граница
`RegistryFilesystem` не получают знаний о Win32 ABI, reparse-буферах или
нативных токенах.

Разделение Windows backend соответствует причинам изменения и не создаёт
нового публичного слоя. Containment решается чистой нормализацией до I/O,
resolver отвечает только за ограниченный обход и владение ресурсами, а
верхний реестр по-прежнему оперирует единым `PlatformAdapter`. Мёртвая
альтернативная точка входа удалена, поэтому бюджетные и parent-relative
инварианты теперь задаются в одном месте.

## D. Читаемость и «Как это работает (просто)»

Имена модулей и функций отражают этапы алгоритма, а заменённые формулировки
докстрингов убирают смешение русских терминов с `handle` и `reparse-target`.
Основной путь читается линейно: проверить запись без перехода по ссылке →
открыть обычный компонент → проверить его тип → вернуть результат или
продолжить от него.

Как это работает (просто): система открывает имя внутри уже открытого
каталога. Если имя оказалось ссылкой, она читает адрес самой ссылки, убеждается,
что адрес остаётся внутри доверенного корня, и снова идёт от корневого
дескриптора по безопасным компонентам. Для сетевого корня адрес того же share
обрабатывается так же, как внутренний локальный адрес. Один счётчик ограничивает
всю цепочку, а временный каталог в каждый момент только один.
