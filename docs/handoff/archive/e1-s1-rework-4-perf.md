входного события.

## Проверка обязательных свойств

- Верхнеуровневая итерация: `islice(event_dict.items(), F)` запрашивает не
  более `min(n,F)` пар. Проверка переполнения через `len(event_dict)` у
  фактического `dict` имеет `O(1)` и не продолжает итератор. Нестроковый ключ
  расходует один из тех же `F` шагов и не может восстановить прежний `O(n)`
  обход. Это закрывает `R3-PERF-001`.
- Строки: `_bounded_text` выполняет первый срез `value[:T+1]`; при усечении
  второй срез также не превышает `T`. Ни ключ, ни диагностическая строка не
  сканируются за пределами 513 исходных символов.
- Значения: для неизвестного строкового ключа сразу записывается
  `[REDACTED]`; для нестрокового ключа — `[UNSUPPORTED]`. В обоих случаях
  значение не читается. Для diagnostic key exact-type проверка принимает
  только `str`, `None`, `bool`, `int`, `float`; контейнеры, пользовательские
  объекты и subclasses получают `[UNSUPPORTED]` без итерации и вызова их
  протоколов.
- Выход: после redaction сериализуется не более 17 полей с ключами и строками
  не длиннее 512 символов. `ensure_ascii=True` делает длину результата равной
  его UTF-8 byte length. Renderer возвращает JSON не длиннее `M-1=8191` байта
  либо короткий фиксированный fallback; вместе с одним логическим LF запись
  не превышает `M`.
- Пиковая работа serializer остаётся ограниченной, хотя fallback выбирается
  после `json.dumps`: `p <= 17`, а грубая верхняя граница для `J` при
  12 ASCII-символах на Unicode code point меньше 210 KiB. Поэтому и этот путь
  имеет фиксированный предел относительно `n`, длины исходных строк и размера
  неизвестных значений.
