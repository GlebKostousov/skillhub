- [P2] [E1-S4-R1-REV-002]
  [`src/skillhub/web/routes.py:30-45,78-87`;
  `src/skillhub/web/_catalog.py:11-13,85-119`;
  `tests/test_skills_catalog.py:478-545`] → `anyio.Lock` берётся до
  `run_in_threadpool()`, поэтому ожидающие POST больше не занимают все worker
  tokens. Однако это очередь, а не single-flight: каждый валидный ожидающий
  запрос после освобождения lock запускает ещё один полный scan; зафиксированный
  сценарий прямо ожидает `calls == 2`. Burst по-прежнему создаёт `O(r)`
  незавершённых запросов, выполняет `r` последовательных файловых загрузок без
  deadline и даёт `O(rF)` суммарной работы.

  Это также пробивает гарантию точного PRG-результата: хранилище удерживает
  только восемь полных поколений. Если до перехода клиента по раннему `303`
  завершатся восемь следующих reload, его marker вытесняется, а
  `for_marker()` молча возвращает текущее поколение без flash. Нужен
  неблокирующий admission (`409`/`429`) либо присоединение всех конкурентных
  callers к одной task/result; новый файловый scan не должен стартовать для
  каждого запроса одного burst. Flash должен иметь определённую одноразовую
  семантику и не терять уже выданный redirect из-за произвольного кольца.

## B. System design, HTTP и конкурентность

- Исходная `E1-S4-REV-001` на уровне route-managed reload закрыта частично
  правильно: `_CatalogGeneration` связывает `LoadReport`, безопасный summary и
  marker, а GET захватывает одну ссылку. Два HTTP POST могут показать каждый
  свой набор карточек и причин через разные marker. Оставшаяся проблема —
  отдельный от registry владелец текущего состояния и неканонический
  `LoadReport.search()`, описанные в R1-REV-001.
- Файловая работа и построение поколения выполняются вне event loop.
  Асинхронный lock больше не отправляет ожидающих callers блокироваться внутри
  общего thread pool; отменённый до lock caller не запускает отложенный scan.
  При этом admission/coalescing отсутствует, поэтому исходная
  load-amplification часть perf finding остаётся открыта как R1-REV-002.
- Host boundary теперь сначала требует ровно один ASCII `Host`, точное
  локальное имя и необязательный десятичный порт `1..65535`, а затем сохраняет
  TrustedHost envelope. Доверенный префикс, userinfo, suffix, path,
  неоднозначный порт, отсутствующий и дублированный Host закрыты.
- Origin по-прежнему сравнивает scheme, casefold-host и нормализованный порт;
  media type и фактическое тело ограничены до разбора формы. Не-ASCII token
  теперь переводится в контролируемый 403, а валидный app-generated token
  сравнивается как bytes через `compare_digest`. Исключение по совместимости
  router seam вынесено в R1-REV-003.
- POST возвращает `303` на `/skills?reload=<marker>`, результат получает
  фокус, а JavaScript заменяет URL на канонический `/skills`, поэтому обычный
  refresh не повторяет мутацию. Человеческие сообщения больше не показывают
  `root_missing`/`missing_description`. Ограничение marker-store при burst
  остаётся частью R1-REV-002.
- Context managers файловой границы и оба lock освобождают ресурсы на выходе.
  `_flashes` ограничен восемью элементами, поэтому утечка памяти не
  неограниченна, но каждый элемент удерживает полный `LoadReport`, включая
  тела скиллов, до вытеснения; это цена текущего непотребляемого flash-cache.

регрессией.

## D. Читаемость и крайние случаи

Положительный поток стал короче: проверить Host/Origin/form/token → получить
async admission → в потоке построить поколение → вернуть 303 → отрисовать один
захваченный результат. Имена новых модулей отражают причины изменения, русские
формулировки и touch/grid-правки закрывают прежние замечания голоса и UX.

Как это работает (просто): приложение хранит готовое поколение каталога и
показывает только его. Перезагрузка перечитывает файлы в рабочем потоке,
создаёт новый marker и после redirect показывает связанный результат. Сейчас
есть два изъяна: сохранённый отчёт может иметь другой порядок и срок жизни,
чем публичный снимок реестра, а concurrent reload не объединяются — они просто
ждут очередь и затем каждый перечитывают диск. После девятого результата
ранняя ссылка может уже не найти своё поколение.

Безопасно обработаны пустой и отсутствующий root, частичная загрузка, будущий
неизвестный issue code, hostile metadata, длинный query, malformed Host,
Unicode token и отмена caller до async lock. Предел marker в 20 цифр закрывает
неограниченный разбор query, но кольцо из восьми поколений не задаёт надёжную
жизнь уже выданного redirect.
