## Дефекты / риски
- [P1] [E1-S1-REV-001] [README.md:11; src/skillhub/core/logging.py:82-103] → штатная команда запуска оставляет журналы `uvicorn.access` и `uvicorn.error` вне настроенного scrubber: живой запуск записал query `material=user-content-secret-42`, а необработанный `RuntimeError` — вместе с `private-runtime-content-84` и полным traceback; безопасный HTTP-ответ этого не предотвращает, потому что Uvicorn повторно журналирует исключение → подключить к штатной точке запуска единую безопасную конфигурацию Uvicorn/structlog, которая не выводит raw target, значения исключений и traceback с пользовательским содержимым, но сохраняет безопасный тип ошибки и request ID.
- [P1] [E1-S1-REV-002] [src/skillhub/core/settings.py:17-23] → `extra="forbid"` отклоняет лишние поля модели, но не неизвестные переменные окружения: при `SKILLHUB_UNEXPECTED=enabled` `Settings()` успешно вернул development-конфигурацию; опечатка в имени настройки поэтому молча включает значение по умолчанию вопреки fail-closed договору → до создания настроек проверять множество имён `SKILLHUB_*` по allowlist полей модели и завершать старт при неизвестном имени.

## System design
`/health` — чистое идемпотентное чтение без состояния, root использует один серверный шаблон, а конфигурация собирается один раз на экземпляр приложения. HTTP-статусы ожидаемых ошибок стабильны, 500 закрыт безопасным телом; целостность observability-пути нарушена в E1-S1-REV-001, а fail-closed источник конфигурации — в E1-S1-REV-002.

## Архитектура
Направление `main → app_factory → web → core` соблюдено; `app_factory.py` остаётся единственным composition root, `core` и `web` имеют фасады, import-linter подтверждает независимость `core`. Преждевременных ports, repositories, plugin framework и прикладного состояния в `core` не добавлено.

## Читаемость / понятность
Имена отражают ответственность, функции короткие, error/security paths симметричны, инварианты безопасного ответа и request ID видны непосредственно в коде.

Как это работает (просто): `main` публикует приложение, которое фабрика собирает из настроек, логирования, middleware и web-маршрутов. Middleware назначает request ID и защитные заголовки, маршруты отдают HTML/health, а централизованные handlers превращают ошибки в безопасный JSON.

## Чего нет / свежесть / повествование
Состав модулей соответствует E1-S1 и каноническим якорям; новых сущностей будущих слайсов нет. `pyproject.toml` и `uv.lock` согласованы, `httpx2` соответствует API `Starlette 1.6.0 TestClient`, локальный Bootstrap совпадает с документированным SHA-256, Git-настройки применены repo-local; Ruff, mypy strict, import-linter, pytest, `uv lock --check` и `git diff --check` завершились успешно.
