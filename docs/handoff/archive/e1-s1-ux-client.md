# Выжимка
Роль: ux-client
Вердикт: НУЖНА_ДОРАБОТКА
Находки: 2 — HTTP-ошибки фреймворка не русифицированы и нарушают единый формат; skip-link не переносит клавиатурный фокус в основное содержимое.

# Отчёт
Рецепт: да

## flow

- Первый запуск по одной команде из README успешен; root сразу и однозначно сообщает «Локальное приложение запущено» и «Сервис работает».
- Страница остаётся читаемой при ширине 320 px, горизонтальной прокрутки и обрезанного текста нет.
- Переход на неизвестный адрес приводит к сырому англоязычному JSON без понятного русского объяснения.

## states

- Success: есть и понятен на root; `/health` отвечает без промежуточных действий.
- Error: применим; централизованные ожидаемые и внутренние ошибки безопасны, но 400/404/405 обходят этот пользовательский формат — finding `UX-ERR-001`.
- Loading, empty, partial: N/A — в E1-S1 нет асинхронной загрузки или набора данных.
- Offline: N/A — это полностью серверный каркас без клиентского runtime; при недоступном процессе состояние показывает сам браузер.

## errors/API

- `/health` имеет понятное имя и стабильное минимальное тело `{"status":"ok"}`.
- Типизированная ошибка и 500 возвращают русский `message`, стабильный `code`, не показывают stack trace или пользовательское содержимое.
- Реальные ответы фреймворка сейчас различаются: 404/405 — `{"detail":"Not Found|Method Not Allowed"}`, неверный Host — английский plain text.

## a11y

- Есть `lang="ru"`, `<title>`, один `<main>`, один `<h1>`, именованный регион и статус; Bootstrap подключён локально.
- Текст и зелёный badge имеют достаточный контраст; root проверен на desktop и 320 px.
- Skip-link видим при Tab, но после Enter `location.hash` меняется на `#content`, а `document.activeElement` остаётся `BODY` — finding `UX-A11Y-001`.

## rule 22

N/A — на root нет форм, полей ввода и отправки данных; сохранение пользовательского ввода и ошибки полей проверить невозможно.

## findings

- [P1] [UX-ERR-001] [HTTP 400/404/405:72-78] → ребёнок видит английские `Not Found`, `Method Not Allowed` или `Invalid host header`, а клиенты получают несовместимые `detail`/plain-text вместо общего `error.code + error.message` → добавить обработку framework HTTP errors и TrustedHost-отказа с ясными русскими сообщениями и единым стабильным телом.
- [P2] [UX-A11Y-001] [root:11-12] → skip-link меняет адрес, но не переносит фокус на `<main>`, поэтому клавиатурный и screen-reader переход к содержимому не подтверждён → сделать `#content` программно фокусируемым, перенести туда фокус при активации и проверить видимый focus state.
