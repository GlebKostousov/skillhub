# Отчёт
Рецепт: да

## Логика / простота vs критерии

- Unknown env закрыт в [`src/skillhub/core/settings.py:14-37`]: `_StrictEnvironmentSource` возвращает неизвестное prefixed-имя в строгую Pydantic-валидацию, поэтому `extra="forbid"` завершает сборку.
- Framework envelope закрыт в [`src/skillhub/web/errors.py:20-134`]: 400/404/405 и fallback используют одну форму `{"error": {"code", "message"}}`; исходный статус сохраняется.
- Duplicate app/service copy закрыт в [`src/skillhub/web/templates/home.html:13-18`]: осталась одна фраза и один термин «приложение».
- Границы слайса сохранены: `app_factory.py` остаётся composition root, registry/LLM/SQLite и новые прикладные ports не появились.
- [P2] [LS-R1-001] [`src/skillhub/core/logging.py:50-340`] → ради одного критерия безопасного машинного лога добавлены отдельный объект бюджета, раздельные обходчики mapping/sequence/scalar, учёт ссылок, перестановка полей, formatter и полный dictConfig; дельта файла составляет `+306/-19`. Нужная рекурсивная зачистка потерялась внутри универсального механизма обхода произвольного графа объектов, что расходится с проектным правилом коротких приватных файлов → оставить один узкий bounded-redactor для поддерживаемых структур и компактную серверную конфигурацию, сохранив зачистку, пределы и обязательные диагностические поля.
- [P3] [LS-R1-002] [`src/skillhub/web/errors.py:137-165`] → `unexpected_error_handler` формирует request id, пишет `http.unexpected_error`, строит 500-envelope и очищает context; тот же алгоритм повторён в `ProcessErrorBoundary` на [`src/skillhub/web/errors.py:250-276`]. Два источника одного ответа уже расходятся по способу отправки и потребуют синхронных правок → выделить одну приватную операцию подготовки unexpected-error события и ответа, а handler и ASGI-boundary оставить тонкими адаптерами.

## Голос проекта с якорями

- [`docs/architecture/decision-rationale.md:103-114`] задаёт короткие приватные файлы, тонкие HTTP-обработчики, централизованный handler, structlog и русские Google-style docstrings. Язык docstrings теперь соответствует этому голосу; объём `logging.py` и дубль unexpected-error — нет.
- [`docs/architecture/skillhub.md:317-320`] требует рекурсивно вырезать транскрипции, протоколы, ответы, ключи и authorization. Rework сохраняет этот смысл; LS-R1-001 требует упростить механизм, а не ослабить зачистку.
- [`docs/phases/orchestrator-e1.md:57-74`] ограничивает S1 запускаемым каркасом, безопасным ответом/логом, fail-closed конфигурацией и минимальным `core`. Unknown env и framework envelope теперь соответствуют договору.
- Проверка docstrings по AST дельты `e8b11d7..cda20c3`: 113 новых строк документации; первые формулировки — описательные (`Проверяет`, `Возвращает`, `Преобразует`, `Собирает` и именные варианты), запрещённых приказов нет.

## Дизайн-решения

- Собственный settings source оправдан ровно одним разрывом договора: стандартный `BaseSettings` не передаёт неизвестные prefixed-переменные в `extra="forbid"`. Новый сервис конфигурации не введён.
- Таблица framework-кодов и общий `_error_response` — достаточная централизация HTTP-envelope. `TrustedHostEnvelopeMiddleware` нужен для plain-text ответа внешнего middleware; отдельный `ProcessErrorBoundary` не должен дублировать содержательную ветку handler.
- Безопасный Uvicorn formatter соответствует отказу без traceback, но его соседство с универсальным bounded traversal создаёт две причины изменения одного 405-строчного модуля.
- Jinja2 и локальный Bootstrap остаются каноническим решением; правка root не добавляет новый визуальный паттерн или клиентский слой.
