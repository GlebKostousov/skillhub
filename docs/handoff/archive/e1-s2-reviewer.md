Вердикт: НУЖНА_ДОРАБОТКА
Находки: 4 — P1: 1, P2: 2, P3: 1.

Главный блокер: `safe_load()` способен выбросить обычный `ValueError`, который
не переводится в `invalid_yaml`; один такой каталог обрывает загрузку всех
скиллов. Дополнительно не определены коллизии канонического `name`, неполна
семантика `has_files` для внутренних directory-symlink и превышен
канонический предел McCabe.

## A. Дефекты / риски

- [P1] [E1-S2-REV-001] [`src/skillhub/registry/_registry.py:81-102`;
  `src/skillhub/registry/_registry.py:150-168`] → `_parse_document()` ловит
  только `RecursionError` и `yaml.YAMLError`, тогда как PyYAML 6.0.3 на
  допустимом для scanner значении вроде `extra: 2023-99-99` выбрасывает
  `ValueError: month must be in 1..12`; `_load_entries()` ловит только
  `_InvalidSkillError`, поэтому один дефектный front matter прерывает весь
  `load()` вместо безопасного issue и скрывает рабочие каталоги → замкнуть все
  ожидаемые ошибки конструирования SafeLoader в стабильный `invalid_yaml` до
  выхода из `_parse_document()`, сохранив изоляцию каждого каталога.
- [P2] [E1-S2-REV-002] [`src/skillhub/registry/_registry.py:81-102`;
  `src/skillhub/registry/_models.py:7-22`; `CONTEXT.md:11-13`;
  `docs/architecture/skillhub.md:90`] → два разных каталога с одинаковым
  валидным `name` безусловно попадают в `LoadReport.skills`; канонический
  снимок `Mapping[str, Skill]` не может представить оба значения, и будущая
  сборка mapping будет молча выбирать запись по порядку каталогов → определить
  глобальную уникальность имени в файловой политике S2 и выдавать стабильный
  collision-reason без молчаливого перезаписывания.
- [P2] [E1-S2-REV-003] [`src/skillhub/registry/_registry.py:213-235`;
  `CONTEXT.md:14`; `docs/phases/orchestrator-e1.md:125-138`] →
  `_has_additional_files()` задаёт `followlinks=False`, поэтому внутренняя
  symlink на каталог с обычным файлом даёт `has_files=False`; при этом
  внутренняя symlink непосредственно на файл учитывается. Это противоречит
  правилу «любой рекурсивный файл» и создаёт две разные семантики для
  разрешённых in-root ссылок → обходить внутренние directory-symlink после
  resolve/containment с защитой от повторного посещения, не заходя во внешние.
- [P3] [E1-S2-REV-004] [`src/skillhub/registry/_registry.py:38-261`;
  `docs/architecture/decision-rationale.md:103-113`;
  `docs/architecture/skillhub.md:355-364`] → один файл объединяет обход,
  containment, чтение, разбор front matter, валидацию моделей, `has_files` и
  логирование; проверка Ruff с утверждённым `McCabe <= 3` показывает шесть
  превышений (`load` 5, `_load_entries` 6, `_resolve_skill_file` 5,
  `_parse_document` 6, `_validated_description` 5,
  `_has_additional_files` 7) → уменьшить ветвление и разделить файловый обход
  и разбор/валидацию по самостоятельным причинам изменения.

## B. System design

- Place: `registry` владеет файловой политикой и моделями, не протекает в
  `core` или `web`; `__init__.py` предоставляет один явный фасад
  (`src/skillhub/registry/__init__.py:1-12`).
- Contracts/errors: `Skill`, `LoadIssue` и `LoadReport` действительно
  неизменяемы за счёт frozen/slots и tuple
  (`src/skillhub/registry/_models.py:6-48`). Большинство отказов становятся
  короткими машинными reason, но E1-S2-REV-001 оставляет дыру в изоляции, а
  E1-S2-REV-002 — дыру в таксономии каталожных коллизий.
- Idempotency/order: сортировка непосредственных записей и tuple дают
  повторяемый результат на неизменном дереве
  (`src/skillhub/registry/_registry.py:71-79`, `81-102`). Порядок
  детерминирован, но не решает неоднозначность двух одинаковых identity.
- SoT: формат `SKILL.md` разбирается в одном месте, однако канонический
  identity будущего `Mapping[str, Skill]` пока не защищён уникальностью.
- Scale: новых процессов, storage, repository/port/plugin-абстракций нет;
  полное чтение ограниченного локального дерева соответствует масштабу E1-S2.
- Observability: каждое переведённое отклонение пишет
  `registry.skill_skipped` с безопасным `skill_path` и `error_code`
  (`src/skillhub/registry/_registry.py:251-257`;
  `src/skillhub/core/_redaction.py:15-29`). Непереведённый `ValueError` из
  E1-S2-REV-001 не создаёт такого события и ломает наблюдаемый контракт.

## C. Архитектура относительно канона

Направление `core ← registry ← web` не нарушено: новый пакет не импортирует
web/composition root, а изменение core ограничено разрешением уже
санитизированного `skill_path`. Публичный фасад, приватные `_models.py` /
`_registry.py`, отсутствие динамического исполнения и зависимость PyYAML
соответствуют канону.

Отклонения: результат S2 пока нельзя без потерь превратить в утверждённый
`Mapping[str, Skill]` при повторяющемся имени; resolved-containment
непоследовательно применяется к внутренним directory-symlink при подсчёте
`has_files`; модуль нарушает зафиксированную границу сложности.

## D. Читаемость и «Как это работает (просто)»

Имена приватных функций и линейный happy path читаются хорошо:
resolve корня → сортировка каталогов → ограниченное чтение → UTF-8 →
front matter → модель → `has_files`. Повторения отчётов малы, а модели
отделены от I/O. Основной минус — 261 строка и шесть функций с ветвлением выше
канона: политика ошибок распределена между `load()`, `_load_entries()`,
`_resolve_skill_file()`, `_parse_document()` и `_reject()`, из-за чего
неполный `except` оказался трудно заметен.

Как это работает (просто): реестр по очереди берёт дочерние каталоги, убеждается,
что разрешённый путь остаётся внутри корня, читает не больше 65 536 байт,
разбирает YAML и тело и возвращает неизменяемые значения. Ошибочный каталог
должен стать коротким предупреждением и не мешать соседям; сейчас это обещание
ломают некоторые значения YAML, а одинаковые имена не имеют однозначного
исхода.

## E. Чего нет / свежесть / повествование

В слайсе присутствуют модели, фасад, bounded reader, UTF-8/YAML/front-matter
валидация, containment, `has_files`, безопасные события, README и обе
зависимости. Преждевременных reload/snapshot/search, HTTP/UI или обработчиков
скиллов нет.

`pyproject.toml:6-13,16-25` и `uv.lock` согласованы: PyYAML 6.0.3 — runtime,
types-PyYAML — dev; lock содержит обе записи и обновлённые metadata проекта.
`git diff --check dd6d135..20748bc` чист. Коммит `20748bc` свежий и является
непосредственным потомком принятого `dd6d135`.

Повествование README корректно описывает bounded safe-YAML путь и неизменяемый
отчёт (`README.md:49-58`), но формулировка «безопасные причины пропуска» пока
сильнее реализации из-за E1-S2-REV-001. До закрытия также отсутствуют
канонические ответы на collision имени и internal directory-symlink в
`has_files`.
