# Выжимка

Роль: logic-simple
Scope: `e4feefa..f2c6b9f`
Вердикт: **НУЖНА_ДОРАБОТКА**
Находки: 3 — P0: 0; P1: 0; P2: 1; P3: 2.

Дельта реализует заявленные маршруты, пять артефактов и общий поиск через
единственный `SkillRegistry`. Веб-слой не читает файлы напрямую, API и страница
используют одну проекцию метаданных, а исполняемого объёма E2 нет. Gate
останавливают несогласованный результат параллельной перезагрузки, чрезмерно
дробная цепочка вспомогательных функций в `security.py` и несколько нарушений
естественного русского голоса.

# Отчёт

## Логика / простота

- [P2] [E1-S4-LS-001] `src/skillhub/web/routes.py:91-126,129-152,245-250` →
  `_CatalogState.reload()` отпускает свою блокировку после публикации отчёта, а
  `reload_skills()` только затем отдельно читает список через
  `self._registry.search("")`. Между этими действиями второй POST может
  опубликовать другой снимок. Первый ответ тогда объединит `loaded/skipped` и
  `issues` первой перезагрузки с карточками второй. Дополнительный
  `_reload_lock` не обеспечивает именно ту согласованность, ради которой
  введён, а один и тот же реестр одновременно принадлежит `_CatalogState` и
  `_Routes` → один владелец состояния каталога должен возвращать итог и
  соответствующий ему список в рамках одной операции; обработчик не должен
  повторно читать реестр после выхода из неё.
- Точные прикладные маршруты дельты: `GET /health`, `GET /`,
  `GET /api/skills?q=`, `GET /skills?q=` и `POST /skills/reload`. JSON-каталог
  и страница различены явно; дополнительных прикладных маршрутов нет.
- Обычный поиск в API и UI проходит через один
  `SkillRegistry.search(q)` и одну `_public_skills()`. Пустая строка возвращает
  снимок целиком, длинная строка даёт 422 в соответствующем формате канала,
  отсутствие совпадений — пустой JSON-массив или отдельное пустое состояние
  страницы.
- Страница различает начальную загрузку, успешную перезагрузку, частичную загрузку,
  полностью пустой каталог, пустой результат поиска и ошибку длины запроса.
  Смысл этих состояний не дублирован в JavaScript: `app.js` меняет только
  промежуточную подпись и состояние кнопки.
- `create_app()` создаёт ровно один `SkillRegistry`, выполняет один начальный
  `reload()` и передаёт тот же объект маршрутам. Второго загрузчика или
  альтернативного списка скиллов нет; `ReloadSummary` хранит только
  представление последнего отчёта, а не копию каталога.
- Поиск по `name` и `caption` и порядок по каноническому `name` остаются у
  фасада registry. Веб-слой не сортирует и не фильтрует результат повторно.

## Дизайн

- Языковая правка по E1-S4-LS-002 не требует нового
  слоя или переименования программного контракта.
- `routes.py` вырос на 313 строк при 15 удалённых и теперь занимает 351 строку:
  в нём находятся семь классов, регистрация маршрутов, HTTP-модели, контекст
  страницы, состояние перезагрузки, проекции и рендер. Сам по себе объём не является
  отдельной находкой, но LS-001 показывает конкретное место, где два владельца
  реестра уже размыли ответственность. Исправление должно сделать владельца
  состояния единым, а не добавлять третий координатор или сервис.
- [P3] [E1-S4-LS-003] `security.py` вырос на 157 строк при одной удалённой и
  теперь занимает
  215 строк. Одна операция разбора заголовка `Origin` проходит цепочку
  `_require_same_origin()` → `_single_header()` / `_parse_origin()` →
  `_split_origin()` → `_is_plain_origin()` / `_canonical_origin()` →
  `_valid_origin_parts()` / `_normalized_port()`. У большинства звеньев один
  вызывающий код и один следующий шаг; для понимания одного инварианта нужно
  переходить между восемью функциями (`security.py:49-115`) → укрупнить эту
  часть до нескольких содержательных фаз разбора и сравнения, сохранив
  отдельными только реально повторно используемые операции. Это замечание о
  форме модуля, а не о правилах проверки запроса.
- `_public_skills()` используется тремя путями, `_reload_summary()` — начальной
  загрузкой и reload, `_render_skills_page()` — всеми HTML-состояниями. Эти
  функции устраняют повтор поведения и не образуют лишние одношаговые
  обёртки.
- В `src/skillhub/web` отсутствуют `Path`, `open`, `read_text`, `read_bytes`,
  YAML и `RegistryFilesystem`. Web импортирует только публичные
  `LoadReport`, `Skill` и `SkillRegistry`; файловая ответственность остаётся в
  registry.
- В рабочем коде нет классификатора, шлюза LLM, обработчиков скиллов,
  транскрипции, исполнения протокола, DOCX или учёта в SQLite. Тела пяти
  `SKILL.md` являются данными E1-S4 и не создают исполняемый объём E2.
