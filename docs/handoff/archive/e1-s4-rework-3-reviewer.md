## B. System design

- Composition root остаётся в `create_app()`: один `SkillRegistry`, одна
  стартовая публикация, один CSRF-токен, фасад `skillhub.web` без
  `app.state` реестра и без второго входного отчёта.
- Владение состоянием однозначно. Реестр — единственный писатель текущего
  поколения под `_reload_lock`. Web-gate (`anyio.Lock`) допускает один
  активный HTTP-scan; конкурентный POST не ждёт и не занимает worker на
  файловую работу. `_CatalogState` владеет только резервацией и Bounded
  flash под `threading.Lock`.
- Читатели без блокировки перезагрузки получают целую старую или новую
  `RegistryCapture`. Присваивание поколения атомарно; карточки и итог одной
  загрузки не смешиваются с другой.
- PRG сохранён: маркер резервируется до scan, flash публикуется после
  checkpoint, 303 ведёт на `?reload=`, первый точный GET делает `dict.pop()`.
  Отмена или ошибка до publish снимает резервацию и не занимает слот.
- Истёкший или неизвестный маркер не отражается и показывает текущее
  поколение без ложного `reload_performed`. Два одновременных GET одного
  маркера не могут оба показать success.
- Направление зависимостей `core ← registry ← web` сохранено. Web читает
  публичные `Skill`, `LoadReport`, `RegistryCapture` и `SkillRegistry`;
  файлы скиллов не импортирует и не исполняет.
- HTTP-поверхность прежняя: четыре GET и один POST, плюс `/static`. JSON
  по-прежнему содержит только `name`, `caption`, `description`, `has_files`.
  Отказ reload больше не является JSON 409 формы: это HTML-состояние
  текущего каталога.

## C. Архитектура относительно канона

Канон E1-S4 требует единый фасад каталога, стабильный порядок по `name`,
защищённый reload и тонкий web над уже существующим registry. Дельта
укрепляет этот канон: текущий список и итог загрузки снова принадлежат
одному опубликованному поколению реестра, а не web-копии.

`RegistryCapture` добавлен в фасад `skillhub.registry` как значение одной
публикации, а не как новый слой. `_CatalogState` сужен до резервации и
одноразовой публичной вспышки. `create_router()` остаётся публичным швом
сборки, но принимает один изменяемый реестр, который сам является SoT.

Поиск фасада по-прежнему задаётся `_search_skills()`. Публичная проекция
собирается из `capture.search("")` или `report.search("")`, поэтому порядок
уже канонический; `_PublicCatalog.search()` только проверяет длину query и
повторяет тот же name/caption casefold. Это проекция поколения, а не второй
владелец снимка.

Новых runtime-зависимостей, хранилищ, plugin-швов и исполняемого объёма E2
нет. Middleware order и Host/Origin path диапазон не менялись.

## D. Читаемость и «Как это работает (просто)»

Положительный путь читается линейно: проверить форму → взять допуск →
зарезервировать маркер → перечитать файлы в рабочем потоке → проверить
отмену → сохранить публичную вспышку → 303 → атомарно показать её на GET.
Имена `capture`, `reserve_reload`, `publish_reload`, `consume` совпадают с
ролью в этом пути.

Как это работает (просто): приложение держит один готовый снимок реестра и
показывает только его. Кнопка reload перечитывает диск, заменяет этот снимок
целиком и на короткое время запоминает понятный итог под случайным адресом.
Если перезагрузка сейчас невозможна, страница говорит об этом и оставляет
прежний список. Забытая ссылка сама протухает; повтор той же ссылки не
показывает успех дважды.

Крайние случаи обработаны явно: пустой и отсутствующий корень, частичная
загрузка, длинный query, неизвестный или просроченный маркер, конкурентный
POST, отмена до публикации вспышки и исчерпание восьми попыток маркера.
