Дельта устраняет смешивание карточек и отчёта: веб-каталог публикует один
неизменяемый объект поколения, а результат каждого POST доступен после
перенаправления по ограниченному маркеру. `routes.py` и `security.py` стали
тоньше, проверки запроса разнесены по связным модулям, цепочка разбора Origin
сокращена, русский текст рабочего кода и интерфейса исправлен. Gate остаётся
закрыт из-за нового расхождения канонического порядка: веб-поиск теперь идёт по
порядку каталогов в `LoadReport`, тогда как фасад реестра сортирует по `Skill.name`.

# Отчёт

## Логика / простота

- [P2] [E1-S4-R1-LS-001]
  `src/skillhub/web/_catalog.py:62-72`,
  `src/skillhub/registry/_models.py:69-86`,
  `src/skillhub/registry/_registry.py:80-92,127-133`,
  `src/skillhub/registry/_filesystem.py:67-82`,
  `src/skillhub/registry/_document.py:88-101` → `_CatalogGeneration.search()`
  использует `LoadReport.search()`. Общая `_search_skills()` сохраняет порядок
  входного iterable, но `LoadReport.skills` собирается в порядке имён каталогов,
  а `SkillRegistry.search()` получает значения снимка, предварительно
  отсортированного по каноническому `Skill.name`. Валидный `SKILL.md` вправе
  задать имя, отличное от имени каталога. Поэтому, например, каталоги `a` с
  `name: z` и `b` с `name: a` дадут в API/UI порядок `z, a`, а публичный фасад
  реестра — `a, z`. Это нарушает критерий единого поиска и стабильного
  канонического порядка и возвращает второй наблюдаемый вариант семантики →
  сортировать вход общей поисковой операции по `Skill.name` либо формировать
  поколение из уже канонически упорядоченного неизменяемого набора; API, UI и
  `SkillRegistry.search()` должны получать один результат для любого валидного
  сочетания имени каталога и поля `name`.
- Прежняя E1-S4-LS-001 закрыта по согласованности данных. Замороженная
  `_CatalogGeneration` связывает один `LoadReport`, производный `ReloadSummary`
  и маркер. `_CatalogState.current` публикуется одним присваиванием; API,
  обычная страница и страница результата захватывают один объект поколения.
  Ограниченная история из восьми поколений позволяет двум завершившимся POST
  показать каждый свой точный результат без повторной загрузки.
- Проверка длины строки и проекция `Skill → SkillSummary` теперь едины для API
  и HTML. Пустая строка возвращает всё поколение, отсутствие совпадений —
  пустой JSON-массив или отдельное пустое состояние, строка длиннее 128
  символов — 422 без отражения исходного значения.
- `create_app()` по-прежнему создаёт один `SkillRegistry` и выполняет одну
  начальную перезагрузку. Веб-слой не читает дерево скиллов и не создаёт второй
  загрузчик.

## Голос + канон

  перезагрузки», документация поиска говорит о наборе результатов, а пустые и
  ошибочные состояния используют прямые пользовательские формулировки.
- Интерфейс последовательно говорит «режим», «название», «системное имя»,
  «каталог» и «перезагрузка». Формулировки «Ищите режим по названию или
  системному имени», «Данные появятся после исправления указанной проблемы» и
  сообщения по кодам причин звучат естественно и не показывают внутренние
  `reason` или корневой путь.
- Подписи пяти режимов совпадают с каноном:
  `business-message` — «Деловое сообщение»,
  `meeting-action-items` — «Задачи встречи»,
  `meeting-protocol` — «Протокол встречи»,
  `text-summary` — «Краткое резюме»,
  `text-translation` — «Перевод текста».
- Новых необязательных англо-русских гибридов в изменённом рабочем коде и UI
  не найдено. Идентификаторы HTTP, Host, Origin, CSRF, `SKILL.md` и имена полей
  используются как технические названия.

  порта; `_single_header()` повторно используется для Origin, Host,

- Направление `registry ← web` сохранено: web импортирует публичные

## Маршруты и состояния

- Объявлены те же пять прикладных маршрутов: `GET /health`, `GET /`,
  `GET /api/skills?q=`, `GET /skills?q=` и `POST /skills/reload`. Отдельно
  остаётся инфраструктурный mount `/static`; новых прикладных маршрутов нет.
- `POST /skills/reload` после проверки формы выполняет одну сериализованную
  загрузку и отвечает 303 на `GET /skills?reload=<marker>`. Маркер не содержит
  токен, тело скилла или путь. JavaScript фокусирует итог и удаляет служебный
  параметр из адреса, не повторяя POST.
- HTML различает начальный каталог, успешную перезагрузку, частичную загрузку,
  полностью не загруженный каталог, существующий пустой каталог, пустой
  результат поиска, ошибку длины и промежуточное состояние кнопки. Клиентский
  код не пересобирает карточки и не дублирует серверные правила.
- Исполняемого объёма E2 в `src` нет: отсутствуют классификатор, шлюз модели,
  обработчики скиллов, разбор протокола, DOCX, транскрипция и SQLite. Пять
  `SKILL.md` и два файла `meeting-protocol/references/` остаются только данными.
