Основной сценарий работает: из главной открывается каталог, видны все пять
режимов, поиск по подписи и имени совпадает с API, reload сохраняет пять

машинными кодами и ведёт в бесполезный цикл повторной перезагрузки, а успешный
reload оставляет пользователя на POST-адресе `/skills/reload` без
Post/Redirect/Get.

# Отчёт

## Рецепт и покрытие

- Прочитаны договор E1-S4, канон, `CONTEXT.md`, README, шаблоны, CSS, JavaScript,
  маршруты и metadata пяти реальных скиллов.
- Штатное приложение запущено из корня командой
  `uv run python -m skillhub --port 8000`.
- Живой браузер: desktop `1440×900`, mobile `390×900` и `320×900`.
- Отдельное временно настроенное приложение с отсутствующим `skills_root`
  проверено в браузере на `320×900`.
- Частичный и отсутствующий каталоги дополнительно подтверждены TestClient:
  `2 passed, 24 deselected` (`--no-cov`).
- Оба локальных сервера остановлены; слушателей на портах 8000/8001 не осталось.
- Скриншоты не сохранялись: все находки ниже имеют точный наблюдаемый текст,
  URL и геометрию; временные browser-артефакты в handoff не переносились.

## Наблюдаемый flow

- Главная: один `h1` «SkillHub», статус «Приложение работает» и заметная ссылка
  «Открыть скиллы». Переход открывает `/skills`.
- Чистый каталог показывает ровно пять карточек в стабильном порядке:
  `business-message`, `meeting-action-items`, `meeting-protocol`,
  `text-summary`, `text-translation`.
- Каждая карточка содержит caption, name, description и понятный текст
  `has_files`; только «Протокол встречи» сообщает о дополнительных файлах.
- Поиск по подписи `ПЕРЕВОД` возвращает только `text-translation`;
  case-insensitive поиск по имени `MEETING-ACTION` возвращает только
  `meeting-action-items`. UI и `/api/skills` совпали.
- Запрос без совпадения показывает «Найдено: 0», отдельный пустой результат,
  совет изменить запрос и ссылку очистки.
- Явно пустой `q=` возвращает все пять карточек.
- Query из 129 символов возвращает 422 и видимый alert:
  «Поиск не выполнен. Поисковый запрос не должен превышать 128 символов.»
  Значение не отражается обратно в поле.
- Перед reload кнопка становится disabled и меняется на «Перезагрузка…»;
  скрытый `role="status" aria-live="polite"` получает текст
  «Каталог перезагружается.»
- Успешный reload показывает `role="status"`:
  «Каталог перезагружен. Загружено: 5. Пропущено: 0.»; пять карточек остаются,
  дубликатов нет.
- В HTML и API не обнаружены `# Назначение`, `# Правила` и фрагменты тела
  инструкций. API отдаёт только `name`, `caption`, `description`, `has_files`.

## Responsive

- `1440×900`: document/body overflow равен 0; контейнер и контролы не выходят
  за viewport.
- `390×900`: overflow 0, карточки складываются в одну колонку шириной
  `351.2px`; поиск и кнопка «Найти» занимают всю доступную ширину.
- `320×900`: client width `305px` из-за вертикального scrollbar, scroll width
  также `305px`; карточки имеют ширину `280.8px`, выходящих элементов нет.
- Главная на `320×900` также не имеет горизонтальной прокрутки; CTA помещается
  целиком.

## Accessibility, focus, contrast

- Дерево содержит `lang="ru"`, banner, именованную основную навигацию, один
  `main`, один `h1`, именованные регионы карточек и пустого результата.
- Searchbox программно подписан «Поиск по имени или подписи»; кнопки имеют
  однозначные accessible names.
- Skip-link — первый Tab-stop. В фокусе он видим; Enter меняет URL на
  `#content` и переносит фокус на `MAIN#content`.
- Клавиатурный фокус на поле и кнопках заметен четырёхпиксельным синим ring.
- Выборочные измерения контраста: основной текст — `14.63:1`; ссылки,
  primary/outline-кнопки и code-текст — `4.50:1`. Нарушений контраста в
  проверенных состояниях не найдено.
- Результат поиска, loading reload и успешный reload имеют status/live
  semantics; отказ каталога имеет `role="alert"`.

## Console, network, assets

- На главной, обычном каталоге и после успешного reload ошибок и предупреждений
  консоли нет.
- Для намеренного HTTP 422 браузер записал только ожидаемое
  `Failed to load resource: 422`.
- Bootstrap, `app.css`, `app.js` и `favicon.svg` загружаются локально с
  `/static/` и отвечают 200/304; favicon отвечает 200.
- POST `/skills/reload` отвечает 200. Объявленных приложением внешних ресурсов
  нет.

## P0–P3

### P2 — Отказ каталога не объясняет проблему и предлагает бесполезное действие

Наблюдение на реально запущенном приложении с отсутствующим `skills_root`:

- alert: «Каталог не загружен»;
- детали: «Идентификатор: `.`; причина: `root_missing`»;
- empty state: «Проверьте безопасное предупреждение выше и повторите
  перезагрузку».

`"."` и `root_missing` — внутренние обозначения, а не естественное объяснение.
Нажатие предложенной кнопки reload повторно показало тот же экран: пользователь
не узнаёт, что отсутствует каталог и что именно нужно проверить. Частичный
TestClient-сценарий аналогично выводит `missing_description` без расшифровки.

Ожидается отображаемая карта кодов в человеческие сообщения и конкретное
действие, например: «Папка каталога не найдена. Проверьте наличие папки
`skills` и повторите загрузку»; для partial — «В `broken-sixth/SKILL.md`
отсутствует описание». Машинный код можно оставить вторичной технической
деталью.

### P2 — Reload заканчивается на POST-странице

После реального нажатия URL становится
`http://127.0.0.1:8000/skills/reload`, а ответ на POST сразу рендерит HTML с
кодом 200. Это ломает ожидаемую навигацию: обычное обновление страницы
повторяет изменяющий запрос или вызывает предупреждение о повторной отправке
формы; прямое повторное открытие этого URL методом GET не является страницей
каталога. После ответа фокус также сбрасывается на `BODY`.

Нужен Post/Redirect/Get: после reload вернуть 303 на `/skills` и показать
одноразовый результат так, чтобы refresh/back/bookmark оставались обычной
навигацией.

### P3 — Пятый режим визуально осиротел на desktop

На `1440×900` grid строится как `4 + 1`: первые четыре карточки занимают
`y=478..782`, а «Перевод текста» один стоит слева на второй строке
`y=798..1078`. В viewport видна только верхняя часть пятой карточки, и один из
пяти равноправных режимов получает менее заметную позицию.

Для пяти элементов лучше устойчивый desktop-ритм `3 + 2` либо центрирование
неполной последней строки.

### P3 — Интерактивные цели на mobile меньше комфортного размера

На ширинах 320/390 поле, «Найти», «Очистить поиск», reload и CTA имеют высоту
`37.6px`; текстовые ссылки навигации — `24px`. Минимум WCAG 2.5.8 в 24px
формально соблюдён, но для уверенного touch-ввода нужен ориентир не менее
`44px` по высоте и более крупная кликабельная область навигации.

### P3 — Вводный текст говорит языком реализации

Фраза «Поиск использует подпись и каноническое имя из одного снимка реестра»
описывает внутреннюю атомарность, а не пользовательскую пользу. «Каноническое
имя» и «снимок реестра» делают простой экран каталога тяжелее для чтения.

Достаточно естественного текста: «Ищите режим по названию или системному
имени».
