Повторная проверка закрывает расхождение канонического порядка и сохраняет
один алгоритм поиска для отчёта, снимка реестра, API и HTML. Штатное
приложение больше не публикует реестр через `app.state`, а корень сборки
использует публичный фасад `skillhub.web`.

сканирования. Непрозрачный маркер хранится в ограниченном наборе, атомарно
потребляется первым GET и не вытесняется более поздней перезагрузкой. Новых
слоёв, взаимозаменяемых сервисов или исполняемого объёма E2 не появилось.

# Отчёт

## Логика / простота

- Диапазон содержит один коммит `0da3ae5`; его непосредственный родитель и
  merge-base — `6da2a10`. Изменены README, семь файлов рабочего кода и три
  тестовых файла.
- Прежняя `E1-S4-R1-LS-001` закрыта. Единственная `_search_skills()` сначала
  упорядочивает вход по `Skill.name`, затем выполняет общий
  поиск без учёта регистра по `name` и `caption`
  (`src/skillhub/registry/_models.py:69-87`).
- `LoadReport.search()` и `SkillRegistry.search()` вызывают именно эту
  функцию, а `_CatalogGeneration.search()` только проверяет HTTP-предел,
  вызывает `LoadReport.search()` и строит публичную проекцию
  (`src/skillhub/registry/_registry.py:80-94`,
  `src/skillhub/web/_catalog.py:65-76`). Отдельной сортировки или фильтра в
  web нет.
- Поэтому допустимое несовпадение имени каталога и поля `name` больше не
  меняет наблюдаемый порядок: отчёт, снимок, API и HTML получают
  канонический порядок `Skill.name`.
- `create_app()` создаёт один `SkillRegistry`, выполняет одну начальную
  перезагрузку и передаёт связанный с ней отчёт одному `_CatalogState`
  (`src/skillhub/app_factory.py:39-65`). Реестр не выставляется через
  `app.state`, поэтому у штатного приложения не осталось второго внешнего
  пути изменения текущего каталога.
- Текущее поколение по-прежнему связывает один неизменяемый `LoadReport`,
  производный `ReloadSummary` и маркер. API и HTML сначала захватывают одну
  ссылку поколения и не смешивают карточки с итогом другой загрузки.

## Допуск и маркер результата

- `_reload_gate.acquire_nowait()` допускает только одну активную
  HTTP-перезагрузку.
  Конкурентный POST немедленно получает типизированный 409
  `reload_unavailable`; он не ждёт очередь и не запускает файловое
  сканирование (`src/skillhub/web/routes.py:83-100`).
- Освобождение допуска находится в `finally`. После завершения рабочего
  потока явная точка отмены не сохраняет результат запроса, который уже
  отменён; новое обращение затем может быть принято.
- Хранилище содержит не более восьми ещё не показанных результатов. При
  заполнении новый POST отклоняется до `registry.reload()`, поэтому уже
  выданное перенаправление не вытесняется, а число загрузок и удерживаемых
  поколений остаётся ограниченным.
- Маркер создаётся `token_urlsafe(32)`, имеет одну строгую ASCII-грамматику
  длиной 43 символа и проверяется до обращения к словарю
  (`src/skillhub/web/_catalog.py:14-17,168-173`).
- `for_marker()` под одной обычной блокировкой удаляет запись через `pop()`.
  Следовательно, из двух одновременных GET только один получает отмеченное
  поколение; повторный, неизвестный или неверно сформированный маркер
  возвращает текущее поколение без ложного статуса перезагрузки
  (`src/skillhub/web/_catalog.py:122-130`).
- Любой GET с параметром `reload` получает `Cache-Control: no-store`.
  Секретный токен формы, тело скилла и путь не включаются в URL.
- Три блокировки имеют разные конкретные обязанности: существующая блокировка
  реестра сериализует файловую публикацию, асинхронный допуск отсекает
  конкурентный HTTP-запрос до общего пула рабочих потоков, а короткая
  блокировка состояния
  защищает словарь одноразовых результатов. Универсального менеджера
  конкурентности или новой иерархии сервисов не введено.

## Состояние приложения и фасад

- `app.state.skill_registry` удалён; совпадений `app.state` в рабочем коде
  нет. Текущее веб-состояние принадлежит замыканию маршрутизатора, а не
  публичному изменяемому контейнеру приложения.
- `StrictHostMiddleware` экспортируется через `skillhub.web.__all__`, и
  `app_factory.py` импортирует все web-компоненты через один публичный фасад
  (`src/skillhub/web/__init__.py:3-19`,
  `src/skillhub/app_factory.py:12-20`).
- Направление `core ← registry ← web` сохранено. Web использует публичные
  `SkillRegistry`, `LoadReport`, `LoadIssue` и `Skill`, не читает файловое
  дерево и не создаёт второй загрузчик.
- Явно заданный CSRF-токен публичного `create_router()` валидируется один раз
  при сборке. Допустимы значения ASCII длиной 1–256, разрешённые в URL, а
  сравнение
  запроса остаётся одним байтовым `compare_digest`
  (`src/skillhub/web/_reload_guard.py:15-43,177-183`).

## Дизайн

- `_CatalogState` остаётся одним владельцем веб-поколения и короткого
  одноразового набора результатов. `_CatalogGeneration` остаётся моделью
  согласованного результата, а `ReloadUnavailableError` — одной конкретной
  транспортной ошибкой.
- Изменение не вводит `Protocol`, слой репозиториев или портов, фабрику
  обработчиков, диспетчер, универсальный кэш или общий пакет помощников.
- `routes.py` сохраняет регистрацию и HTTP-оркестрацию; `_catalog.py` владеет
  представлением и состоянием каталога; `_reload_guard.py` проверяет
  недоверенный запрос. Причины изменения модулей не смешаны.
- Пять прикладных маршрутов сохранены: четыре GET и один POST. `/static`
  остаётся инфраструктурным подключением.
- В рабочей дельте нет классификатора, шлюза модели, обработчиков скиллов,
  разбора протокола, DOCX, транскрипции или SQLite. E2 не захвачен.
