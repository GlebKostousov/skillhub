Rework исправляет канонический порядок поиска, убирает реестр из `app.state`,
вводит неблокирующий admission для reload, делает flash-marker случайным и
атомарно одноразовым, валидирует публичный CSRF-контракт при сборке router и
возвращает `StrictHostMiddleware` в фасад `skillhub.web`.

Gate остаётся закрыт по двум причинам. Публичный `create_router()` всё ещё
принимает отдельно изменяемый `SkillRegistry` и начальный `LoadReport`, поэтому
внешний поддерживаемый caller может навсегда рассинхронизировать реестр и HTTP.
Кроме того, восемь выданных, но не прочитанных redirect заполняют flash-store
навсегда; после этого reload отвечает 409 до перезапуска процесса, а каждый
слот удерживает полный непубличный `LoadReport`.

## B. System design, HTTP и конкурентность

- Канонический порядок закрыт: общий `_search_skills()` сортирует любой вход
  по `Skill.name`; `LoadReport.search()`, `SkillRegistry.search()`, API и HTML
  получают одинаковую последовательность при несовпадении имени каталога и
  front-matter `name`. `E1-S4-R1-LS-001` закрыт.
- `app.state.skill_registry` удалён, поэтому стандартный factory больше не
  публикует прямой обход HTTP-владельца. Оставшийся публичный обход через
  `create_router()` описан в `E1-S4-R2-REV-001`.
- Активный reload действительно single-flight по принятой стратегии отказа:
  `acquire_nowait()` допускает один scan, конкурентный POST немедленно получает
  409 и не занимает worker token. `finally` освобождает admission при
  исключении или отмене, а checkpoint не сохраняет flash отменённой во время
  scan операции.
- Marker имеет 256 бит CSPRNG-входа, строгую ASCII URL-safe grammar и
  атомарный `dict.pop()` под `threading.Lock`. Первый конкурентный GET получает
  flash, повторный и неизвестный marker — текущее поколение без ложного
  `reload_performed`; marker-страница получает `Cache-Control: no-store`.
  Наблюдаемая replay-часть `SEC-E1S4-R1-001` и
  `QA-E1S4-R1-001` закрыта.
- Защита уже выданного redirect от кольцевого вытеснения реализована, но
  невосстанавливаемая заполненность store заменяет потерю старого результата
  постоянной недоступностью новых reload — `E1-S4-R2-REV-002`.
- Фактический middleware order и строгий Host/Origin path диапазон не меняет:
  process boundary и security headers остаются снаружи strict Host, затем
  TrustedHost и маршруты.

## C. API, ресурсы и модули

- Публичный CSRF router contract теперь честный: при сборке принимается только
  URL-safe ASCII длиной 1–256, неверная конфигурация сразу даёт `ValueError`,
  а runtime сравнивает точные ASCII bytes. `E1-S4-R1-REV-003` закрыт.
- `StrictHostMiddleware` экспортирован через `skillhub.web`, а composition root
  больше не импортирует приватную раскладку пакета.
  `E1-S4-R1-REV-004` закрыт.
- HTTP-поверхность остаётся прежней: четыре GET и один POST, плюс
  инфраструктурный `/static`. JSON по-прежнему содержит только `name`,
  `caption`, `description`, `has_files`; тело инструкций и абсолютные пути не
  проецируются.
- Направление `core ← registry ← web` сохранено, прямого файлового доступа из
  web и исполняемого объёма E2 нет. `_catalog.py` владеет web-поколением и
  flash, `_reload_guard.py` — входным протоколом reload, `routes.py` —
  HTTP-оркестрацией.
- Ресурсы одного scan ограничены прежними S2-бюджетами, активный worker reload
  ограничен единицей. Невосстанавливаемые восемь flash-слотов и удержание
  полных старых отчётов остаются `E1-S4-R2-REV-002`.

## D. Читаемость и крайние случаи

Положительный путь читается прямо: валидация запроса → неблокирующий admission
→ scan вне event loop → cancellation checkpoint → сохранение одноразового
flash → 303 → атомарное потребление на GET.

Malformed, Unicode и неизвестный marker не отражается и не меняет состояние.
Два одновременных GET не могут оба показать success. При заполненном store
новый scan не начинается, поэтому уже выданный результат не вытесняется.
Однако отсутствие срока жизни превращает обычный незавершённый PRG в
необратимый расход capacity; после восьми таких операций пользовательский путь
reload больше не восстанавливается сам.

Имена и локальные обязанности новых функций соответствуют коду. Главная
неясность интерфейса остаётся архитектурной, а не синтаксической:
`create_router(registry, initial_report)` выглядит как обычная dependency
injection, хотя корректность требует скрытого эксклюзивного владения обоими
аргументами.
