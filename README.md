# SkillHub

Локальный каталог пяти режимов ассистента на Python 3.13 и FastAPI. Для
запуска не нужны `.env` и ключ модели: без `DEEPSEEK_API_KEY` приложение
стартует, а генерация честно возвращает `generation_unavailable`. Ключ
читается только из `DEEPSEEK_API_KEY`, без префикса `SKILLHUB_`.

## Подготовка

Установите [uv](https://docs.astral.sh/uv/) и синхронизируйте окружение из
зафиксированного файла `uv.lock`:

```console
uv sync --frozen
```

## Запуск

Из корня репозитория выполните:

```console
uv run python -m skillhub --port 8000
```

Это единственная поддерживаемая команда процесса: она привязывает сервер к
`127.0.0.1`, отключает журнал доступа и применяет безопасные события запуска.

`skillhub.main:app` — публичная точка интеграции для ASGI-сервера, а не вторая
пользовательская команда запуска. При её импорте действуют те же строгая
проверка настроек, безопасный отказ старта и конфигурация журналирования
приложения. Адрес, порт и журнал доступа в таком режиме задаёт внешний
ASGI-сервер.

Необязательная переменная `SKILLHUB_ENVIRONMENT` принимает только
`development`, `test` или `production`; по умолчанию используется
`development`. Файлы `.env` не читаются, а неверные значения и неизвестные
переменные `SKILLHUB_*` останавливают запуск.

После старта:

- `http://127.0.0.1:8000/` — окно ассистента: поля «Что нужно сделать» и
  «Материал для обработки», бейдж выбранного режима и список режимов только
  для чтения;
- `http://127.0.0.1:8000/api/assistant` — `POST` с JSON `{intent, material}`;
  CSRF — заголовок `X-CSRF-Token` и/или поле `csrf_token` в JSON, плюс точный
  `Origin`; успех возвращает `{selected_skill, caption, outcome, text, message}`;
- `http://127.0.0.1:8000/skills?q=` — страница «Скиллы»: поиск и перезагрузка;
- `http://127.0.0.1:8000/api/skills?q=` — каталог в формате JSON;
- `http://127.0.0.1:8000/health` — готовность процесса, `{"status":"ok"}`;
- `http://127.0.0.1:8000/protocol` — проверка готового протокола и выгрузка
  `protocol.docx`; без ключа кнопка «Собрать черновик» выключена.

`POST /api/assistant` принимает только UTF-8, ограничивается 1 МБ и проверяет
точный `Origin`. Секрет CSRF передаётся заголовком `X-CSRF-Token` и/или полем
`csrf_token` в JSON. Поля `intent` и `material` остаются прикладными. Снимок
режимов берётся из реестра, а не из тела запроса. Без ключа исход —
`generation_unavailable`. Выбранный `meeting-protocol` собирает нормативный
Markdown через `create_draft`; структурная ошибка даёт публичное сообщение
разбора. Word скачивается со страницы `/protocol`.

Штатный каталог `skills/` содержит пять режимов. Страница и API показывают их
в порядке канонического имени:

| Имя | Подпись |
|---|---|
| `business-message` | Деловое сообщение |
| `meeting-action-items` | Задачи встречи |
| `meeting-protocol` | Протокол встречи |
| `text-summary` | Краткое резюме |
| `text-translation` | Перевод текста |

Поиск страницы, API и реестра сравнивает только имя и подпись без учёта
регистра и сохраняет этот порядок. Пустой `q` возвращает всё текущее
поколение. Строка длиннее 128 символов отклоняется с кодом `query_too_long`;
её значение не журналируется.

Каталог в формате JSON возвращает только `name`, `caption`, `description` и
`has_files`. Тело инструкций и файловые пути в HTTP-контракт не входят.

Перезагрузка выполняется формой `POST /skills/reload` и завершается
перенаправлением на страницу «Скиллы». Случайный секрет CSRF создаётся для
каждого экземпляра, передаётся только в скрытом поле и проверяется вместе с
точным `Origin`. Отсутствующий, `null` или чужой источник отклоняется; CORS и
запасной межсайтовый путь не включены. Тело формы ограничено 4096 байтами.
Если перезагрузка сейчас недоступна, браузер остаётся на каталоге с понятным
предупреждением; сырой ответ об ошибке форма не показывает.

Ожидаемые и системные HTTP-ошибки возвращаются в единой оболочке
`{"error":{"code":"...","message":"..."}}`. Приложение и сервер записывают
ограниченные JSON-события без исходных значений ошибок и содержимого запросов.

Приложение предназначено для локального использования и принимает только
доверенные имена хоста. CORS не включён.

## Файловый реестр

`SkillRegistry` читает непосредственные каталоги заданного корня и возвращает
неизменяемый `LoadReport` с валидными скиллами и безопасными причинами
пропуска. `Skill`, `LoadIssue` и `LoadReport` неизменяемы; файлы разбираются
только как данные через `yaml.safe_load`, не импортируются и не исполняются.

```python
from pathlib import Path

from skillhub.registry import SkillRegistry

registry = SkillRegistry(Path("skills"))
preview = registry.load()
print(preview.loaded, preview.skipped)

report = registry.reload()
generation = registry.capture()

for skill in generation.search("протокол"):
    print(skill.name, skill.caption, skill.has_files)

print(report.loaded, report.skipped, generation.report.loaded)
```

При создании реестра файловое дерево не читается: свойство `snapshot` содержит
пустое неизменяемое отображение. Публичные операции имеют разный смысл:

- `load()` заново читает дерево и возвращает самостоятельный полный отчёт, но
  не меняет снимок и не берёт блокировку перезагрузки;
- `reload()` сериализуется с другими вызовами `reload()`, полностью загружает
  и проверяет дерево и публикует новый `RegistryCapture` одним присваиванием;
- `capture()` без блокировки возвращает отчёт и снимок одного поколения;
  `snapshot` — проекция того же поколения. Ранее полученная ссылка остаётся
  пригодной для чтения после следующего `reload()`;
- `search(query)` читает одно поколение, сопоставляет `query` с `name` и
  `caption` через Unicode casefold и возвращает кортеж в каноническом
  порядке. Пустой запрос возвращает все элементы снимка.

`LoadReport.loaded` равен числу элементов `skills`, а `skipped` — числу
безопасных причин в `issues`. Если корень отсутствует, не является каталогом
или недоступен, `skills` остаётся пустым, а `issues` содержит одну безопасную
причину с путём `"."`.

Публичная константа `MAX_SKILL_FILE_BYTES` равна 65 536 байтам. Лимит
проверяется до UTF-8-декодирования и YAML-разбора; отдельного настраиваемого
предела тела нет, потому что весь `SKILL.md` уже ограничен этим значением.
YAML-якоря, псевдонимы и пользовательские теги отклоняются до загрузки данных.

Одна загрузка ограничена 256 записями корня, 128 обрабатываемыми каталогами
скиллов и 1 048 576 суммарными байтами `SKILL.md`. Обход дополнительных файлов
ограничен 1024 записями и глубиной 32. Эти внутренние бюджеты не настраиваются;
переполненный список корня даёт один пустой отчёт с причиной, а исчерпание
бюджета каталогов или байтов останавливает обход после уже принятых скиллов.
Превышение бюджета дополнительных файлов пропускает только текущий скилл.

Настроенный корень строго разрешается и сверяется с фактически открытым
каталогом до перечисления. Все дальнейшие операции идут через семантическую
файловую границу относительно уже открытого корня и родительских каталогов.
Ссылки POSIX, символические ссылки и соединения каталогов Windows допускаются
только при конечной цели внутри того же корня. Для сетевого корня внутренняя
UNC-цель того же общего ресурса подчиняется тому же правилу; внешний путь,
другой ресурс и служебное пространство имён отклоняются до чтения.

При совпадении канонического `name` побеждает первый каталог в стабильном
порядке, а каждый последующий получает причину `duplicate_name`, поэтому
молчаливой перезаписи нет. `has_files` означает наличие хотя бы одного
дополнительного обычного файла внутри разрешённого дерева; пустые каталоги и
внешние цели не считаются. Причины и предупреждения содержат только стабильный
код и безопасный идентификатор каталога, без тела файла, абсолютного пути и
трассировки.

## Политика Git

`.gitignore` исключает секреты, локальные окружения, результаты проверок,
сборки и редакторов. `.gitattributes` хранит текст в LF, оставляет CRLF только
для `.bat` и `.cmd` и помечает бинарные форматы.

После клонирования примените настройки только к этому репозиторию:

```console
git config --local core.autocrlf false
git config --local core.safecrlf true
git config --local fetch.prune true
git config --local pull.ff only
git config --local push.autoSetupRemote true
```

Проверить нормализацию и источник настроек можно командами
`git ls-files --eol` и `git config --local --list --show-origin`.
